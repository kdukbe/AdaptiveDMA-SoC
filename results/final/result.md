# 최종 Adaptive 보드 실험 결과

## 실험 조건과 검증 결과

- 보드: Arty Z7-20
- PL clock: 100 MHz
- 부하 순서: CPU1 `OFF -> ON -> OFF -> ON`, 3회 반복
- 측정 수: 구간당 25개, 모드당 300개, 총 2,100개 sample
- DMA 명령: 8 MiB 메모리 복사
- 비교 모드: 7개
- 최종 UART 결과: PASS
- 원본 로그 재계산: PASS
- 데이터 무결성 및 DMA counter 검사: PASS

CPU1 OFF 상태의 CPU-only baseline은 `95.04 cycles/access`입니다.
하한과 상한은 baseline의 130%, 150%인 `123.55`, `142.56 cycles/access`입니다.

## 부하 변화에 따른 Adaptive 동작

| CPU1 상태 | Sample 수 | L0 선택 수 | L1 선택 수 | CPU 평균 | 상한 초과 수 | DMA MiB/s |
|---|---:|---:|---:|---:|---:|---:|
| OFF | 150 | 49 | 101 | 132.29 | 11/150 | 467.49 |
| ON | 150 | 147 | 3 | 134.58 | 6/150 | 385.78 |

Controller는 OFF 구간 sample의 67.3%에서 제한이 완화된 `L1`을,
ON 구간 sample의 98.0%에서 CPU 보호 단계인 `L0`를 선택했습니다.
단계 전환은 상승 5회, 하강 8회로 총 13회였습니다.
CPU1 부하 변화에 따라 CPU feedback으로 RBR 비율이 조절되는 것을 확인했습니다.

이 보드 실험에서는 `L0`와 `L1`이 선택되었습니다.
`L2`와 `L3`를 포함한 전체 단계 전환은 RTL 시뮬레이션에서 검증했습니다.

## 처리량과 CPU 지연의 Trade-off

고정 설정인 `RBR 50%`는 상한 초과 0회를 기록했습니다. Adaptive의 결과는 다음과 같습니다.

- RBR 50% 대비 DMA 처리량: `381.46 -> 426.12 MiB/s`, `11.71%` 증가
- RBR 50% 대비 상한 초과율: `0.00% -> 5.67%`
- Fixed maximum 처리량 대비 `61.78%` 확보
- Fixed maximum 대비 상한 초과율: `100.00% -> 5.67%`

측정한 설정들에서 Adaptive는 처리량과 상한 초과율 사이의 Pareto 동작점에 해당합니다.
상한 초과 0회를 우선하면 RBR 50%가 적합했고, Adaptive는 5.67%의 상한 초과율에서
처리량을 11.71% 높였습니다.

## 측정값 검증

`analyze.py`로 원본 로그에서 다음 항목을 재계산하고 출력값과 비교했습니다.

- 전체 2,100개 sample
- 구간별 집계 28개와 모드별 전체 집계 7개
- UART에 출력된 최솟값·평균·P95·P99·최댓값·상한 초과 수
- 명령 수와 cycle 수로 계산한 구간별·전체 DMA 처리량
- 구간별 counter 합계
- 상승·하강을 포함한 Adaptive 단계 전환 13회

보드 프로그램의 각 명령 검사와 전체 메모리 비교가 통과했습니다.
CPU1은 부하 buffer를 19회 순회했고 checksum `0x00064000`을 출력했습니다.

## 결과 자료

- `raw.log`: 원본 UART sample, 단계 선택, 구간별 통계와 DMA counter
- `summary.csv`: 모드별 비교와 상한 초과율
- `trace.svg`: Latency, 상한·하한 및 Adaptive 단계 변화
- `tradeoff.svg`: DMA 처리량과 상한 초과율 비교
